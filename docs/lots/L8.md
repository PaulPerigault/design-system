  disque :

    (`src/media` couvre `packages/astro/src/media`), rapport `fichier:ligne: message`, codes

    (ADR-0002), testé ;
  - `check-size` (max, extensions, racines) et `check-layers` (couches ordonnées, imports ES, CSS
    et `.astro`, par chemin ou nom de paquet ; échec si aucun fichier n'appartient à une couche) ;
  - `check-images` : `<img>` brut et `background-image: url(` hors `src/media` ; JPEG (APP1 Exif
    avec GPSInfo en `II`/`MM`, XMP) et PNG (`eXIf` avec GPS, `iTXt`/`tEXt`/`zTXt` XMP) lus à la
    main, bornés, sans exception sur fichier corrompu ; commande `exiftool` de nettoyage ; budget
    `maxKb` et `budgets` par chemin ;
  - `src/eslint.mjs` : `designRules`, `testRelaxations`, `designConfig()` ;
    `eslint.design-rules.mjs` de la racine les réexporte (lint du dépôt inchangé) ;
  - binaire `bin/pp-guards.mjs` : `pp-guards <contrôle>|all [options] [racines…]`,
    `pp-guards.config.json` implicite ou `--config`, `check-tokens` intact et branché par un
    adaptateur ;
  - `pp-guards.config.json` du dépôt : `all` passe sur `packages`, `apps`, `tools` avec une seule
    exception motivée (`packages/tokens/generated`, `color-literal`).
- **`@paulperigault/create`** (`packages/create/`), `node:util` `parseArgs` strict, `io` injecté,
  aucune dépendance d'exécution :
  - `create <dossier>` : site Astro consommateur (`@paulperigault/css`, `@paulperigault/tokens`,
    `astro`, `@paulperigault/guards` dans `verify`, Husky + commitlint sans signature d'outil, CI
    `npm ci --ignore-scripts` aux actions épinglées, `.npmrc` npmjs), versions exactes dans
    `templates/versions.json`, instantané de l'arborescence et des sha256 ; refuse un dossier non
    vide ;
  - `add <élément>` : dépendance exacte ajoutée au `package.json` (indentation, CRLF, minifié
    conservés), extrait d'import, avertissement si l'export manque ;
  - `eject <élément>` : copie vers `src/components/pp/`, `pp-ds.lock.json` (version, sha256 par
    fichier), refus atomique sans `--force` ;
  - `diff <élément>` : modifié (local, paquet), ajouté, supprimé ; code 1 si différent ;
  - `--dry-run` sur toute commande qui écrit, raccourci `npm create @paulperigault <dossier>`.

Un seul `bin` suffit : `npx @paulperigault/create …` et `npm create @paulperigault <dossier>`
lancent le binaire unique d'un paquet. Les fichiers point du gabarit sont versionnés préfixés `_`
(`_npmrc`, `_gitignore`, `_github/`, `_husky/`) car `npm pack` écarte `.npmrc` et `.gitignore` ;
la CLI les renomme.

### Bit exécutable des binaires

`git update-index --chmod=+x packages/guards/bin/pp-guards.mjs packages/create/bin/pp-create.mjs`
(confort local ; npm pose le bit à l'installation). Un exécutant ne peut pas le faire : le
formatage Prettier du dispatcher réécrit le fichier et perd le mode (échec de T8.22).

### `packages/astro/package.json`

Ajouter `"registry"` à `files` : `add`, `eject` et `diff` lisent
`node_modules/@paulperigault/astro/registry/items/*.json`.

### `package.json` (racine)

- `"check:guards": "node packages/guards/bin/pp-guards.mjs all --config pp-guards.config.json"`,
  ajouté à `guard` (après `check:lockfile`). Il couvre `check:tokens` (sans l'étape
  `npm -w @paulperigault/tokens run check`, à garder) et `check:size` : ces deux scripts peuvent
  rester tels quels ou être remplacés plus tard.

### `release-please-config.json` (à trancher)

`packages/create/templates/versions.json` fixe les versions des paquets `@paulperigault/*` du
site généré. release-please ne les met pas à jour seul : soit `extra-files` (type `json`,
`jsonpath`), soit un plugin `linked-versions`. Tant que rien n'est fait, ces versions restent
`0.0.0` et doivent être relevées à la main à chaque publication.

### `.github/workflows/ci.yml` : job « générer un site puis verify »

À ajouter, et `site` à ajouter aux `needs` du job `ci`. Les paquets `@paulperigault/*` ne sont pas
encore publiés : le site généré est branché sur les tarballs du commit (`npm pack`), installés
ensemble pour que `@paulperigault/css` trouve `@paulperigault/tokens` 0.0.0 local.

```yaml
site:
  # Génère un site consommateur avec la CLI, l'installe sur les paquets du commit, puis verify.
  runs-on: ubuntu-latest
  timeout-minutes: 20
  steps:
    - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7
      with:
        persist-credentials: false
    - uses: actions/setup-node@949feb2413d6458794dcd2491c4babbbce0c15c1 # v7
      with:
        node-version-file: .nvmrc
        cache: npm
    - run: npm ci --ignore-scripts
    - name: paquets du commit
      run: |
        mkdir -p "$RUNNER_TEMP/packs"
        npm pack --pack-destination "$RUNNER_TEMP/packs" \
          -w @paulperigault/tokens -w @paulperigault/css -w @paulperigault/guards
    - name: site généré
      run: node packages/create/bin/pp-create.mjs create "$RUNNER_TEMP/site"
    - name: installation sur les tarballs
      working-directory: ${{ runner.temp }}/site
      run: |
        git init -q
        npm install --no-audit --no-fund "$RUNNER_TEMP"/packs/*.tgz
    - name: verify du site
      working-directory: ${{ runner.temp }}/site
      run: npm run verify
```

`git init` sert au script `prepare` (`husky`) ; `npm install` des tarballs remplace les versions
`0.0.0` du gabarit par des `file:` dans le seul site jetable du runner. Non exécuté localement :
je n'ai pas le droit d'écrire hors de `tasks/` et `docs/lots/`, ni de lancer les binaires du lot
à la main (refusé) ; à valider au premier passage en CI.
