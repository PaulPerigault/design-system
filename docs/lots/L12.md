# Lot L12 — mobile d'abord, ordinateur excellent

## Produit

- T12.01 matrice de 13 appareils (4 téléphones en portrait et paysage, tablette, 3 bureaux,
  mouvement réduit) : axe, cibles 24 et 44 px, espacement du texte (1.4.12).
- T12.02 reflow à 320 px (1.4.10), texte à 200 % (1.4.4), survol non indispensable, mesure à 1920.
- T12.03 `enterkeyhint` sur `Input` et `Textarea`.
- T12.04 focus visible, contrasté et jamais masqué (2.4.7, 2.4.11, 2.4.13).
- T12.05 menu mobile en `Dialog` natif, testé sur la matrice.
- T12.06 police du corps préchargée (une seule), budgets à 360 × 800, CPU ×4, Slow 4G :
  LCP ≤ 2,5 s, INP ≤ 200 ms, CLS ≤ 0,1, JavaScript ≤ 1 Ko gzip.
- T12.07 régression visuelle : `matrix/visual.spec.ts` (actif avec `PP_VISUAL=1`), workflow
  `visual.yml` (références mises en cache par appareil sur le runner, jamais versionnées).

## Vérifications

`npm run verify` vert ; `npm run e2e` : 2870 tests passés, 1198 ignorés (visuel hors CI).

## Décisions et écarts

- Le menu mobile étant un `Dialog`, le repli des Invoker Commands est chargé sur chaque page
  (un seul fichier, mesuré dans le budget JavaScript) : le test « seulement sur ses pages » de
  `dialog.spec.ts` est devenu « un seul script partagé ».
- Exécutants Kiro : `.github/**` est refusé en écriture par le profil ; `visual.yml` écrit par
  l'orchestrateur (SHA de `actions/cache` v6.1.0 et `actions/upload-artifact` v7.0.2 lus via `gh`).
- Deux tâches Playwright lancées en parallèle se disputent le port 4321 (T12.06 a échoué sans
  rien mesurer) : une seule tâche e2e à la fois.
- Les références visuelles n'existent qu'après le premier passage de `visual.yml` sur `develop`.
