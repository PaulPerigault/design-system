# Lot L18 — composants de niveau 2 (1/2)

## Produit

Six composants Astro, zéro JavaScript, chacun avec test de rendu, page au gabarit L13, exemple vivant,
fragment de registre et axe sans violation sur 13 appareils : EmptyState, Skeleton, Stat, Timeline,
Pagination (avec `pageWindow`, fonction pure testée) et Card (lien étendu : un seul lien couvre la
carte, les éléments du pied de carte restent utilisables). « Badge d'état » du brief = `Status`
(déjà livré en L5) : pas de doublon.

## Ce que le lot a appris

- **Le gabarit de page couple chaque composant à quatre fichiers partagés** : la navigation, le
  registre assemblé, `llms.txt` et les données MCP. Une tâche isolée ne peut pas construire la
  documentation avant que ces fichiers connaissent son composant : les six tâches ont toutes
  échoué à `astro build` pour cette seule raison. Leur code était bon. Le lot a donc été intégré
  ensemble : l'orchestrateur a posé la navigation, régénéré le registre et les données MCP, puis
  corrigé. Pour la suite : poser navigation et exports **avant** de lancer les tâches, avec une
  page provisoire par composant, ou limiter l'acceptation à `vitest` et `tsc` et construire la
  documentation une fois par lot.
- **Collision de casse sous macOS** : la tâche T18.05 listait `Pagination.test.ts` et
  `pagination.test.ts`, qui sont le même fichier sur APFS. Le worker a fusionné les deux tests.
  Ne jamais lister deux noms qui ne diffèrent que par la casse.
- **Les contrôles e2e ont attrapé un vrai défaut** : Skeleton masquait son libellé à l'œil
  (`clip-path`, 1 px). Les contrôles 1.4.4 et 1.4.12 le signalent comme texte coupé. Le libellé est
  maintenant visible, ce qui est aussi plus clair pour les personnes malvoyantes.
- Card dépassait 120 lignes : le CSS est passé dans `card.css` (global, `:global()` retiré).
- `llms.test.ts` comptait 31 composants en dur ; il suit désormais la navigation.

## Coût et routage

Six tâches, 11,5 crédits : haiku-5.5 sur EmptyState, Skeleton, Stat, Timeline (0,23 à 0,43 chacune,
code correct, bloqué par le build) ; sonnet-5.5 sur Pagination (6,16) et Card (4,09).
Les tâches de haiku-5.5 ont toutes produit un code exploitable : le palier léger suffit pour des
composants simples quand l'énoncé donne un modèle.
