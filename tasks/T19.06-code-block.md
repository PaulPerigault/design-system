Composant tier 2, accessible (WCAG 2.2 AA), mobile d'abord, dans `packages/astro/src/content/`.
**Zéro JavaScript par défaut** : le contenu et les fonctions de base marchent sans script ; un
comportement éventuel est un `<script>` Astro du composant (bundlé en fichier externe, CSP
`script-src 'self'`) qui importe un module de `packages/astro/src/behaviors/`. Lis d'abord
`AGENTS.md`, puis `packages/astro/src/feedback/Status.astro` (variantes `data-*`, jetons, en-tête) et
son test `packages/astro/test/Status.test.ts` (`renderDom` de `./render`), et, pour un behavior,
`packages/astro/src/behaviors/invokers.ts` avec `packages/astro/test/invokers.test.ts` (DOM injecté
avec linkedom, `vi.fn`). Règles : aucun attribut `style`, jetons `--pp-*` uniquement (liste dans
`packages/tokens/generated/tokens.json` : n'en invente aucun), propriétés logiques, aucun texte en
dur (libellés en props), jamais la couleur seule, ni dégradé, ni ombre, ni flou, aucun nombre
magique (constantes nommées), `import type` pour les types. Fichiers ≤ 120 lignes (découpe en
`.css` global ou en modules si besoin). Cibles tactiles ≥ `--pp-size-target-min`.

## CodeBlock

Bloc de code avec **coloration au build** (aucun JavaScript pour colorer) et bouton de copie. La dépendance `shiki` 4.5.0 est déjà installée dans `packages/astro`. Coloration : `packages/astro/src/content/highlight.ts` (fonction async `highlight(code, lang)`) utilise `createHighlighter` et `codeToTokens` de `shiki` avec le thème **`createCssVariablesTheme()`** : les couleurs de jeton sont alors `var(--shiki-token-keyword)` et semblables, **jamais une valeur brute**. Rends chaque jeton en `<span class="pp-tok" data-tok="keyword">` en **mappant la variable CSS à une valeur de `data-tok`** (aucun attribut `style` : CSP stricte). Définis ensuite dans `code-block.css` les `--shiki-token-*` à partir de jetons `--pp-*` existants (liste dans `packages/tokens/generated/tokens.json`, n'en invente pas), contrastes ≥ 4,5:1 sur le fond du bloc **dans les deux thèmes** (vérifie avec `contrast` de `@paulperigault/tokens`). Langages chargés : `ts`, `js`, `json`, `shellscript`, `astro`, `css`, `html`, `yaml` (liste fermée) ; langue inconnue = texte sans coloration. API : `code: string`, `lang?: string`, `label?: string` (nom accessible du bloc), `copyLabel: string`, `copiedLabel: string` (aucun texte en dur), `filename?: string`. Rendu `<figure>` ; `<pre tabindex="0">` (défilable au clavier) ; bouton `<button type="button" data-copy hidden>` que le script rend visible (sans JavaScript, il reste masqué). `behaviors/copy.ts` (`<script>` du composant) : `navigator.clipboard.writeText`, annonce `copiedLabel` dans un `role="status"`, bouton laissé masqué si l'API est absente ; `install(root)` et fonction pure `textOf(pre)` testées. Le CSS va dans `code-block.css` (global, importé par le composant).

Le champ `Props` documente chaque propriété. **Déjà posés par l'orchestrateur** : l'export
`@paulperigault/astro/CodeBlock.astro`, l'entrée de navigation, un fichier de composant, une page et
un fragment de registre provisoires que tu **remplaces** (mets le schéma shadcn comme
`status.json`, `"tokens": []` : `npm run registry` les recalcule ; liste dans `files` du fragment
tous les fichiers du composant, y compris `.css` et behaviors). Le test couvre : rôles, noms
accessibles, attributs selon les props et défauts, aucun attribut `style`, un cas limite par prop,
et la logique pure des behaviors.

Page de doc `apps/docs/src/pages/components/code-block.astro` sur le gabarit
`../../components/ComponentPage.astro` exactement comme `components/status.astro` (lis-la : `slug`,

vers la norme WCAG ou le motif APG qui s'applique) ; les exemples vivants sont dans
`components/examples/code-block.astro`. Français simple, phrases de 25 mots au plus, faits seulement.
Chaque affirmation d'accessibilité cite un critère WCAG numéroté ou un motif APG ; ce que tu n'as
