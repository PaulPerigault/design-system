config publiée par `@paulperigault/guards`, sans changer le comportement du lint du dépôt.

1. `packages/guards/src/eslint.mjs` exporte :
   - `designRules` et `testRelaxations` : **mêmes valeurs** qu'aujourd'hui ;
   - `designConfig({ testFiles } = {})` → tableau de config plate ESLint :
     `[{ rules: designRules }, { files: testFiles, rules: testRelaxations }]`, avec
     `testFiles` par défaut `['**/*.test.{ts,mjs,js}', '**/test/**/*.ts', '**/e2e/**/*.ts']`.
   - Commentaire d'en-tête : la règle `@typescript-eslint/no-magic-numbers` suppose le greffon
     `typescript-eslint` chargé par le consommateur (le paquet n'a aucune dépendance d'exécution).
   - Les seuils (40, 8, 3, 4, 3) sont des **constantes nommées** : la règle `no-magic-numbers`
     s'applique à ce fichier, contrairement à `eslint.design-rules.mjs`.
2. `eslint.design-rules.mjs` (racine) devient une simple réexportation :
   `export { designRules, testRelaxations } from './packages/guards/src/eslint.mjs';` avec son
   commentaire mis à jour. Ne modifie pas `eslint.config.mjs`.
