gap.md n° 30. Le portfolio a déjà un `llms.txt` (`~/dev/PaulPerigault.githun.io/public/llms.txt`,
lecture seule : copie la structure, pas le contenu). Format : https://llmstxt.org (titre `#`,
résumé en citation `>`, sections `##` de listes `- [titre](url): description`).

1. `lib/llms.ts` (pur, testé) : `buildLlms({ groups, items, site })` renvoie le texte de
   `/llms.txt` : `# Design system @paulperigault`, citation de deux phrases (ce qu'est le système,
   pour qui : sites d'un seul auteur, Astro, tokens `--pp-*`), puis les sections « Composants »
   (un lien par composant vers `/components/<slug>.md`, avec la `description` du registre ; les
   groupes de `navigation.ts` donnent l'ordre), « Documentation » (identité, accessibilité,
   glossaire, recherche : HTML), « Registre » (`/r/registry.json`, schéma shadcn), « Pour les
   IA » (règles : utiliser les composants du système, jetons `--pp-*` seulement, aucun attribut
   `style`, ne pas inventer de composant ; `llms-full.txt`). URL absolues construites à partir de
   `site` (`https://design.paulperigault.dev`). Pas de formule creuse.
2. `pages/llms.txt.ts` : endpoint Astro statique (`GET` renvoie `text/plain; charset=utf-8`) ;
   données : `GROUPS` et `hrefOf` de `navigation.ts`, `@paulperigault/astro/registry.json`.
3. Test : titre, présence des 31 composants, aucun lien relatif, liens `.md` bien formés, pas de
   ligne vide en double.

`llms-full.txt` et les pages `.md` sont produits par une autre tâche (T14.03) : ne les crée pas,
ne fais que les citer. Fichiers ≤ 120 lignes, pas de `any`, français.
