Petite fonction maison (pas de dépendance, pas de `tailwind-merge`) pour composer des classes de
variantes, utilisée par les composants (Button, Field…) avec `class:list`.

```ts
const button = variants({
  base: 'pp-button',
  variants: {
    tone: { primary: 'pp-button--primary', quiet: 'pp-button--quiet' },
    size: { m: '', l: 'pp-button--l' },
  },
  defaults: { tone: 'primary', size: 'm' },
  compound: [{ when: { tone: 'quiet', size: 'l' }, class: 'pp-button--quiet-l' }],
});
button({ tone: 'quiet', size: 'l' }); // 'pp-button pp-button--quiet pp-button--l pp-button--quiet-l'
type ButtonProps = VariantProps<typeof button>; // { tone?: 'primary' | 'quiet'; size?: 'm' | 'l' }
```

- Types inférés depuis la configuration (`as const` inutile pour l'appelant) ; valeur inconnue =
  erreur de compilation ; `defaults` rend les clés facultatives.
- Résultat : classes dans l'ordre base → variantes (ordre des clés) → composées, sans doublon ni
  espace en trop, chaînes vides ignorées.
- `class` externe **non** accepté par `variants` (placement seulement, géré par le composant).
- Tests : comportement (défauts, surcharge, composées multiples, chaînes vides) et types avec
  `expectTypeOf` de Vitest (`VariantProps`, refus d'une valeur inconnue avec `// @ts-expect-error`).
