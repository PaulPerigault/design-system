Le dépôt s'applique ses propres garde-fous. Écris `pp-guards.config.json` à la racine (lis
`packages/guards/src/cli.mjs`, `config.mjs` et chaque `check-*.mjs` pour le format exact des
sections) tel que `pp-guards all --config pp-guards.config.json` passe **sans modifier aucun
autre fichier**.

- `tokens` : équivalent du script `check:tokens` de `package.json` (`packages/tokens/generated/tokens.json` ;
  racines `packages/css/src`, `packages/astro/src`, `apps/docs/src`).
- `design` : racines `packages`, `apps` ; liste blanche **minimale et motivée** (champ `reason`) :
  sources des règles (`packages/guards`), tokens générés et source DTCG (`packages/tokens`), tests
  et e2e qui citent volontairement les motifs interdits (`test`, `e2e`), page de comparaison des
  directions d'identité si elle contient des couleurs littérales (ADR-0002). Préfère une entrée
  `{ path, rules }` restreinte aux seules règles déclenchées à une entrée globale.
- `size` : racines `packages`, `apps`, `tools`, `max` 120, extensions `.ts`, `.astro`, `.css`, `.mjs`.
- `layers` : `tokens` (`packages/tokens/src`, `packages/tokens/scripts`, paquet
  `@paulperigault/tokens`) ← `css` (`packages/css/src`, `packages/css/scripts`,
  `@paulperigault/css`) ← `astro` (`packages/astro/src`, `@paulperigault/astro`).
- `images` : racines `packages`, `apps` ; `allow` `src/media` ; budget par défaut.

Si un contrôle signale un **vrai** défaut dans une source (pas un faux positif), ne l'ajoute pas à
la liste blanche : arrête-toi et décris-le dans ton compte rendu (fichier, ligne, règle). Si c'est
un faux positif du contrôle, décris-le aussi (règle, extrait) : il sera corrigé dans le contrôle.
