Composant tier 2, accessible (WCAG 2.2 AA), mobile d'abord, dans `packages/astro/src/forms/`.
**Zéro JavaScript par défaut** : le contenu et les fonctions de base marchent sans script ; un
comportement éventuel est un `<script>` Astro du composant (bundlé en fichier externe, CSP
`script-src 'self'`) qui importe un module de `packages/astro/src/behaviors/`. Lis d'abord
`AGENTS.md`, puis `packages/astro/src/feedback/Status.astro` (variantes `data-*`, jetons, en-tête) et
son test `packages/astro/test/Status.test.ts` (`renderDom` de `./render`), et, pour un behavior,
`packages/astro/src/behaviors/invokers.ts` avec `packages/astro/test/invokers.test.ts` (DOM injecté
avec linkedom, `vi.fn`). Règles : aucun attribut `style`, jetons `--pp-*` uniquement (liste dans
`packages/tokens/generated/tokens.json` : n'en invente aucun), propriétés logiques, aucun texte en
dur (libellés en props), jamais la couleur seule, ni dégradé, ni ombre, ni flou, aucun nombre
magique (constantes nommées), `import type` pour les types. Fichiers ≤ 120 lignes (découpe en
`.css` global ou en modules si besoin). Cibles tactiles ≥ `--pp-size-target-min`.

## Combobox

Champ avec liste de suggestions (motif APG « Combobox with List Autocomplete », `aria-autocomplete="list"`, **sans** sélection automatique à la saisie). API : `label: string`, `name: string`, `id: string`, `options: { value: string; label: string }[]`, `value?: string`, `hint?: string`, `noResultsLabel: string`, `countLabel: string` (avec `{count}`), `required?`, `invalid?`. Réutilise `Field` et `Input` (lis `packages/astro/src/forms/Field.astro` et `Input.astro` : étiquette, aide, erreur, `aria-describedby`) au lieu de dupliquer. Rendu : `<input role="combobox" aria-expanded aria-controls aria-autocomplete="list" aria-activedescendant autocomplete="off">` et `<ul role="listbox" id>` avec des `role="option"` (`id` stables, `aria-selected`). **Sans JavaScript**, le champ reste un `<input list>` natif avec un `<datalist>` ; le script retire le `list` natif et active la liste ARIA. Comportement (`behaviors/combobox.ts`), logique pure d'abord : `filterOptions(options, query)` (insensible à la casse et aux accents) et `reduceKey(state, key)` : Flèche bas et haut (ouvrent, déplacent l'option active, bouclent), Entrée (valide l'option active), Échap (ferme ; un second Échap vide le champ), Tab (ferme sans valider), Home et End restent au curseur du champ. Le focus **reste dans le champ** (`aria-activedescendant`). Une zone `role="status"` annonce le nombre de résultats (`countLabel`, ou `noResultsLabel` à 0). Cibles ≥ `--pp-size-target-min` ; liste limitée en hauteur (jeton) et défilable ; l'option active défile dans la vue. Tests : logique pure exhaustive et rendu.

Le champ `Props` documente chaque propriété. **Déjà posés par l'orchestrateur** : l'export
`@paulperigault/astro/Combobox.astro`, l'entrée de navigation, un fichier de composant, une page et
un fragment de registre provisoires que tu **remplaces** (mets le schéma shadcn comme
`status.json`, `"tokens": []` : `npm run registry` les recalcule ; liste dans `files` du fragment
tous les fichiers du composant, y compris `.css` et behaviors). Le test couvre : rôles, noms
accessibles, attributs selon les props et défauts, aucun attribut `style`, un cas limite par prop,
et la logique pure des behaviors.

Page de doc `apps/docs/src/pages/components/combobox.astro` sur le gabarit
