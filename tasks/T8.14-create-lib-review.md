Le socle `packages/create/src/lib/*.mjs` (T8.08) est intégré ; une revue a relevé les points
ci-dessous, tous à corriger. Ne change pas les signatures publiques (d'autres commandes s'appuient
dessus en parallèle) : seulement des validations en plus et des tests. `lib.test.mjs` est à la
limite de 120 lignes : déplace des tests vers `io.test.mjs` et `registry.test.mjs`.

1. `test/lib.test.mjs` (conflits de `applyPlan`) : le test ne prouve pas « rien n'est écrit ».
   Partir de `fakeIo({ '/projet/a.txt': 'old' })` avec un plan `a.txt` + `b.txt`, vérifier que
   `files['/projet/b.txt']` est `undefined`, `out` vide, et que `err` cite `a.txt`.
2. Recherche par `title` : ajouter `{ name: 'button', title: 'Bouton' }` et vérifier que
   `findItem(items, 'bouton')` le renvoie.
3. `registry.mjs` `parseItem` : exiger `data.files.every((f) => typeof f?.path === 'string')` ;
   cas ajouté aux fragments invalides (message avec le chemin du fragment).
4. `applyPlan` avec `{ dryRun: true }` sans `force` sur un fichier existant : test qui fixe code
   `1`, conflit sur `err`, rien sur `out`.
5. `nodeIo` : test sans disque avec faux `stdout`/`stderr` (`{ write: (s) => buf.push(s) }`) :
   `io.cwd` et `io.out('x')` → `'x\n'`.
6. `io.mjs` : un `cwd` qui n'est pas absolu au sens POSIX (cas Windows `C:/p`) → `Error` explicite
   « chemin de travail non POSIX : Windows non pris en charge pour l'instant », testé.
7. `packageVersion` : JSON invalide → `Error` avec le chemin ; `version` non chaîne → `Error`.
8. `lock.mjs` `readLock` : `items` qui n'est pas un objet simple (tableau, chaîne) → `Error`.
9. `itemFiles` : refuser aussi un chemin normalisé en `.` (vide ou `packages/astro/`).
10. `test/fake-io.mjs` `fakePackage` : importer `REPO_PREFIX` et `PACKAGE_NAME` depuis
    `../src/lib/registry.mjs` et ne retirer le préfixe que s'il commence le chemin.
