`add`, `eject` (T8.10) et `diff` (T8.11) de `packages/create/src/commands/` sont intégrés et
approuvés ; les revues ont laissé ces remarques, à traiter. Lis les trois commandes et
`snippet.mjs`. Ne change ni le contrat de commande ni les messages existants. `add.mjs` est
près de la limite : la lecture et la réécriture du `package.json` du projet peuvent aller dans
`manifest.mjs` (avec son test).

1. `add` : un `package.json` valide qui n'est pas un objet simple (`null`, `[]`) fait planter ou
   écrit un tableau. Message sur `io.err`, code `1`.
2. `add` et `eject` : un paquet installé sans `version` chaîne non vide donne une dépendance
   vide ou un verrou sans version. Refus, code `2`, dans la localisation commune
   (`snippet.mjs`). Tests pour les deux commandes.
3. `add` : un manifeste en CRLF est réécrit en LF ; détecter `\r\n` et le conserver.
4. `add` : un manifeste minifié (une ligne) est réécrit indenté ; sans indentation détectée,
   sérialiser sans indentation.
5. `add` : seules les clés exactes d'`exports` sont reconnues ; accepter aussi un motif de
   sous-chemin (`"./*.astro"`, `"./*"`) qui couvre l'export, sinon l'avertissement reste. Tests.
6. `eject` : test « paquet absent → code `2` et `npm i @paulperigault/astro` sur `io.err` ».
7. `diff` : le nom est cherché tel quel dans le verrou (`diff Stack` échoue alors que
   `eject Stack` a inscrit `stack`). Recherche insensible à la casse sur les clés du verrou, et
   élément du registre retrouvé par `findItem` (nom ou titre). Test.
