Langage simple (gap.md n° 23) : un terme technique est défini une fois, puis lié.

- `lib/glossary-web.ts` (termes du web et de l'accessibilité : contraste WCAG, ARIA, focus visible,
  cible tactile, zone sûre, reflow, LCP, INP, CLS, Core Web Vitals, `dialog`, `popover`, propriété
  logique, requête de conteneur, mouvement réduit, lecteur d'écran, RGAA, WCAG, CSP) et
  `lib/glossary-project.ts` (termes du projet : jeton, OKLCH, gamut, DTCG, ADR, registre, Invoker
  Commands, SBOM, provenance npm, MCP, `llms.txt`) exportent chacun un tableau `Entry[]` ; `lib/glossary.ts`
  définit le type `Entry`, et `GLOSSARY: readonly Entry[]` d'au moins 30 termes en les fusionnant, triés par ordre alphabétique français (`localeCompare('fr')`) :
  jeton (token), OKLCH, gamut, contraste WCAG, DTCG, CSP, ARIA, focus visible, cible tactile,
  zone sûre, reflow, LCP, INP, CLS, Core Web Vitals, ADR, registre, Invoker Commands, `dialog`,
  `popover`, propriété logique, requête de conteneur, mouvement réduit, lecteur d'écran, RGAA,
  WCAG, SBOM, provenance npm, MCP, `llms.txt`. Définitions d'une à deux phrases courtes
  (≤ 25 mots), exactes ; pas de formule creuse ; si tu n'es pas sûr d'un fait, ne l'écris pas.
- `lib/glossary.test.ts` : identifiants uniques, ordre alphabétique, aucune définition de plus de
  25 mots par phrase, aucune définition vide.
- `components/Term.astro` : `<Term id="oklch">OKLCH</Term>` rend `<a href="/glossaire/#oklch">`
  avec le contenu en slot, et lève une erreur de build si l'identifiant n'existe pas.
- `pages/glossaire.astro` : page sur `DocsLayout` (titre `Glossaire · Design system · Paul
Perigault`), `<h1>`, une liste de définition `<dl>` où chaque `<dt id={id}>` est une ancre.

Contraintes `AGENTS.md` : fichiers ≤ 120 lignes (chaque fichier ; un terme = 3 lignes au plus), pas de `any`, jetons `--pp-*` seulement, français.
