Contrôle `check-images` de `@paulperigault/guards` (kickoff §4 « Garde-fous »), bâti sur le socle
`packages/guards/src/lib/*.mjs` (T8.01 : `listFiles`, `matchesAny`, `lineOf`, `report`,
`GuardUsageError`, `test/fake-io.mjs`). Aucune dépendance : lecture binaire à la main.

## Contrat de module

`export const name = 'images'`, `export const defaults`, `export const cliOptions`
(`node:util` `parseArgs`), `export function run(options, io)` → `0` | `1` (via `report`).
`options` arrive fusionné par la CLI (T8.06) ; `options.roots` reçoit les positionnels.

Défauts : `roots: ['src', 'public']`, `allow: ['src/media']`, `maxKb: 500`, `budgets: []`.

## 1. Balisage (`images/markup.mjs`)

- `<img` brut (insensible à la casse, `<img>` ou `<img …`) dans `.astro`, `.html`, `.md`, `.mdx`,
  `.jsx`, `.tsx` ; `background-image: url(` et `background: … url(` dans `.css` et les `.astro`.
- Permis dans les chemins de `allow` (règle `matchesPath` : `src/media` couvre aussi
  `packages/astro/src/media/`). `<Image`, `<Picture` et `url()` d'une police (`@font-face src:`)
  ne sont pas visés. Commentaires `/* */` et `<!-- -->` neutralisés, lignes conservées.
- Message : `fichier:ligne: <img> brut interdit hors src/media : utiliser Photo` (ou
  `background-image: url( interdit …`).

## 2. Métadonnées (`images/jpeg.mjs`, `images/png.mjs`, `images/metadata.mjs`)

- `metadataOf(bytes)` → liste de constats (`['exif', 'gps', 'xmp']`, vide si propre), format
  reconnu par la signature (pas par l'extension) :
  - **JPEG** : parcours des segments après `FFD8` jusqu'à `FFDA` (SOS) ; APP1 commençant par
    `Exif\0\0` → `exif`, et `gps` si l'IFD0 contient la balise `0x8825` (GPSInfo), boutisme `II`/`MM`
    respecté ; APP1 XMP (`http://ns.adobe.com/xap/1.0/\0`) → `xmp`. Longueurs de segment lues en
    gros-boutiste.
  - **PNG** : signature vérifiée, chunks parcourus jusqu'à `IEND` ; `eXIf` → `exif` ;
    `iTXt`/`tEXt`/`zTXt` de mot-clé `XML:com.adobe.xmp` → `xmp`, `Raw profile type exif` → `exif`.
- **Robustesse** (entrée non fiable) : jamais de lecture hors limites, aucune boucle infinie sur
  une longueur nulle ou incohérente, aucune exception ; un fichier tronqué ou corrompu rend ce
  qui a été lu avant la corruption.
- Fichiers lus : `.jpg`, `.jpeg`, `.png` (insensibles à la casse) ; les autres formats ne sont pas
  analysés (consigner la limite dans un commentaire d'en-tête).
- Message : `fichier: métadonnées exif, gps (vie privée) : nettoyer avec exiftool -all= -overwrite_original "<fichier>"`.

## 3. Budget (`images/budget.mjs`)

- Images visées : `.jpg`, `.jpeg`, `.png`, `.webp`, `.avif`, `.gif`, `.svg`.
- `budgets` = `[{ "path": "src/assets/hero", "maxKb": 400 }]` : l'entrée au `path` le plus long
  qui couvre le fichier l'emporte, sinon `maxKb`. 1 Ko = 1024 octets (constante nommée).
- Message : `fichier: <n> Ko > budget <max> Ko`.
- `maxKb` non positif → `GuardUsageError`.

## Critères

- Fixtures **construites en mémoire** dans les tests (octets JPEG avec APP1 Exif `II` et `MM`, avec
  et sans GPS, APP1 XMP, PNG avec `eXIf`, `iTXt` XMP, PNG propre, fichiers tronqués, longueur de
  segment nulle, longueur qui déborde) ; aucun fichier binaire versionné.
- Signatures et marqueurs en constantes nommées (chaîne hexadécimale ou `latin1`) : aucun nombre
  magique hors tests ; fonctions ≤ 40 lignes, complexité ≤ 8.
- `no-undef` actif : importe `Buffer`, `TextDecoder`… depuis `node:*`.
