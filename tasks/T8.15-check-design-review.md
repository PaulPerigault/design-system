`check-design` (`packages/guards/src/check-design.mjs`, `src/design/*.mjs`, T8.02) est intégré ;
une revue a relevé les points ci-dessous, tous fondés. Lis le code avant de corriger. Ne change
ni le contrat du module (`name`, `defaults`, `cliOptions`, `run`, `checkText`) ni les
identifiants de règles. Si un fichier de test dépasse 120 lignes, déplace des cas vers
`test/design-scope.test.mjs`.

1. `css-rules.mjs` `COLOR_PROPERTY` : n'accepte qu'un segment après `border` ; les propriétés
   logiques `border-inline-start`, `border-block-end-color` passent. Accepter jusqu'à deux
   segments (`border(?:-[a-z]+){0,2}`), idem pour `outline`, et un cas refusé
   `border-inline-start: 1px solid red`.
2. `class-rules.mjs` `TOKEN` : coupe sur les virgules **dans** les crochets
   (`bg-[rgba(0,0,0,0.5)]` devient quatre jetons, non reconnus). Découpage qui tient compte des
   crochets (la virgule sépare toujours les éléments de `class:list` hors crochets), et cas refusés
   `bg-[rgba(0,0,0,0.5)]`, `grid-cols-[1fr,2fr]`.
3. `class-rules.mjs` : `\b(?:class|className|class:list)` attrape `data-class="shadow-md"`.
   Utiliser `(?<![\w-])`, avec un test permis.
4. Tailwind v4 `p-(--x)` / `bg-(--brand)` est une valeur arbitraire : la refuser
   (`arbitrary-value`) **sauf** si la variable est un token `--pp-…` (`p-(--pp-space-m)` permis,
   c'est l'usage des tokens). Tests des deux cas.
5. Tests de `fichier:ligne` hors `.css` : un `.astro` avec frontmatter, `class="shadow-md"` en
   ligne 5 et `color: #fff` dans un `<style>` en ligne 9 → lignes `[5, 9]`.
6. Neutralisation des commentaires HTML réellement testée :
   `<!-- shadow-md 🎉 <p class="shadow-md"> -->` dans un `.astro` et un `.md` → aucun problème.
7. Portée par extension : un `.md` contenant `color: #fff; <p class="shadow-md">` → aucun problème
   CSS ni de classe ; dans un `.astro`, `<p>color: red;</p>` hors `<style>` n'est pas du CSS.
8. Couleur nommée hors propriété de couleur permise : `a { grid-area: red; animation-name: tan; }`
   → aucun problème.
