Page `/pwa/` : la PWA comme **brique optionnelle** du design system, pour les futurs sites.
Lis `apps/docs/src/lib/pwa.ts`, `apps/docs/src/pages/manifest.webmanifest.ts`,
`apps/docs/src/lib/sw-core.js`, `apps/docs/scripts/sw.mjs`, `apps/docs/public/pwa/register.js`,
`apps/docs/scripts/pwa-icons.mjs` et décris ce qu'ils font réellement : le manifeste (champs,
couleurs lues dans les jetons), les icônes dérivées du logo sans le modifier, la stratégie du
service worker (réseau d'abord pour les pages, cache d'abord pour `/_astro/*` et `/pwa/*`, jamais
de cache pour `/pagefind/*` ni hors origine), la mise à jour explicite (bouton, `SKIP_WAITING`),
l'absence de collecte, les contraintes CSP (`worker-src 'self'`, `manifest-src 'self'`, script
externe), l'en-tête `Cache-Control: no-cache` sur `/sw.js`, et les étapes pour l'activer dans un
autre site. Section « Limites » honnête : seules les pages déjà visitées sont lisibles hors
ligne ; pas de précache ; le test `apps/docs/e2e/pwa.spec.ts` (tâche T17.04) le vérifie ; aucune
note Lighthouse n'est revendiquée (la catégorie PWA a été retirée de Lighthouse 12 : ne cite que
si tu as une source). Titre `PWA installable · Design system · Paul Perigault`, description unique
de 120 à 160 caractères, un seul `<h1>`. Réutilise `Alert`, `Table`, `Prose`, `Stack` de
`@paulperigault/astro` (lis leurs `Props`), jetons `--pp-*`, aucun `style` en ligne, aucun CSS
brut. Phrases de 25 mots au plus, faits seulement. Les liens depuis d'autres pages
appartiennent à l'orchestrateur.
