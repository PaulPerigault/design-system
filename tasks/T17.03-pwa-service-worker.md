P3 PWA, 2/3. Service worker **minimal, sans collecte de données**, généré après le build.
`lib/sw-core.js` (JS pur, ESM, testé) : stratégie « réseau d'abord, repli sur le cache » pour les
navigations (`request.mode === 'navigate'`) et « cache d'abord » pour `/_astro/*` et `/pwa/*`
(fichiers à empreinte) ; **jamais** de cache pour les requêtes hors même origine, pour les
méthodes autres que GET, ni pour `/pagefind/*` (index de recherche : réseau seulement). Cache
nommé par version (`pp-docs-<version>`) ; `activate` supprime les autres caches `pp-docs-*`.
**Mise à jour explicite** : pas de `skipWaiting()` automatique ; le worker attend un message
`{ type: 'SKIP_WAITING' }`. Fonctions pures exportées et testées avec des dépendances injectées
(`caches`, `fetch`) : `routeFor(request)`, `handleFetch`, `purgeOldCaches`.

`scripts/sw.mjs` : après le build, écrit `dist/sw.js` en concaténant `sw-core.js` (sans ses
`export`) et un en-tête avec la version (empreinte SHA-256 tronquée de la liste des fichiers de
`dist`), liste précachée = `/`, `/hors-ligne/`… **seulement** les pages déjà visitées sont mises
en cache (pas de précache global) ; pas d'`import` externe. Test : le `sw.js` produit est de
l'ESM-free script valide (`new vm.Script`), contient la version, ne contient aucune URL absolue
`http`. `public/pwa/register.js` : script de 30 lignes au plus, **fichier externe** (CSP
`script-src 'self'`, pas d'attribut en ligne) ; enregistre `/sw.js` si `serviceWorker` existe,
n'enregistre rien sinon ; quand un worker `waiting` existe, ajoute un bouton « Mettre à jour »
dans un `<div role="status">` créé en JS (texte français, cible ≥ `--pp-size-target-min` via
classe `pp-pwa-update`) et envoie `SKIP_WAITING` au clic puis recharge sur `controllerchange`.
Pas de `localStorage`, pas de cookie, pas de réseau tiers. Le branchement dans `DocsLayout.astro`,
`package.json` (script de build) et la CSP appartiennent à l'orchestrateur.
