gap.md n° 24 : index statique Pagefind (déjà installé : `pagefind` 1.5.2, `npm -w @paulperigault/docs
run build` lance `pagefind --site dist` après `astro build`, index dans `dist/pagefind/`).
L'interface par défaut de Pagefind n'est pas documentée comme accessible : on écrit la nôtre.
Tu n'as **pas** le droit de modifier `DocsLayout.astro` ni `package.json` (l'orchestrateur
branche la recherche).

1. `pages/recherche.astro` (page `/recherche/`, `DocsLayout`, titre `Recherche · Design system ·
Paul Perigault`) : `<search>` contenant `<label for>`, `<input type="search" id
autocomplete="off" enterkeyhint="search">`, un bouton « Rechercher » (cible ≥ 44 px), une
   zone `role="status"` (`aria-live="polite"`) qui annonce « N résultats pour « … » » ou
   « Aucun résultat », et une liste `<ol role="list">` de résultats (titre en lien, extrait).
   Sans JavaScript : un paragraphe explique que la recherche demande JavaScript (balise
   `<noscript>`), les pages restent atteignables par le sommaire.
2. `components/SearchBox.astro` : le formulaire et le script. JavaScript **chargé à la demande** :
   `import('/pagefind/pagefind.js')` à la première saisie ou au premier focus, jamais au
   chargement de la page (budget `perf.spec.ts` : ≤ 1 Ko gzip au chargement). Script en module
   `<script>` d'Astro (pas de script en ligne : CSP stricte sans `unsafe-inline`), aucun
   attribut `style`. Recherche déclenchée à l'envoi du formulaire et après 300 ms d'arrêt de
   frappe (constante nommée) ; le focus reste dans le champ ; Échap vide le champ.
3. `lib/search-results.ts` (pur, testé) : `summary(count, query)` (texte annoncé, pluriel
   correct, requête échappée dans le texte) et `normalize(raw)` qui transforme un résultat
   Pagefind (`url`, `meta.title`, `excerpt` avec balises `<mark>`) en `{ url, title, excerpt }` :
   l'extrait n'a que du texte et des `<mark>` (échappe le reste, tout HTML étranger est neutralisé).
4. `styles/search.css` : jetons `--pp-*` seulement, propriétés logiques, focus visible hérité du
   design system, `mark` lisible dans les deux thèmes (couleur de fond et de texte par jetons
   existants, contraste ≥ 4,5:1 ; lis `packages/tokens/generated/tokens.css`).
5. `e2e/search.spec.ts` : sur `/recherche/`, saisir « Dialog » → au moins un résultat vers
   `/components/dialog/`, le statut annonce le nombre, la navigation au clavier atteint le
   premier résultat par Tab ; axe sans violation (`@axe-core/playwright` comme dans
   `a11y.spec.ts`, relis-le) ; aucun script avant le premier focus.

Les pages à indexer reçoivent `data-pagefind-body` sur `<main>` : c'est l'orchestrateur qui
l'ajoute à `DocsLayout`. Pour ton test, il suffit que la page `/components/dialog/` soit trouvée
(Pagefind indexe `<body>` à défaut). Fichiers ≤ 120 lignes (découpe en lib si besoin, dans tes
fichiers), pas de `any`, français.
