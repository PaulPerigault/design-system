Composant tier 2, accessible (WCAG 2.2 AA), mobile d'abord, dans `packages/astro/src/media/`.
**Zéro JavaScript par défaut** : le contenu et les fonctions de base marchent sans script ; un
comportement éventuel est un `<script>` Astro du composant (bundlé en fichier externe, CSP
`script-src 'self'`) qui importe un module de `packages/astro/src/behaviors/`. Lis d'abord
`AGENTS.md`, puis `packages/astro/src/feedback/Status.astro` (variantes `data-*`, jetons, en-tête) et
son test `packages/astro/test/Status.test.ts` (`renderDom` de `./render`), et, pour un behavior,
`packages/astro/src/behaviors/invokers.ts` avec `packages/astro/test/invokers.test.ts` (DOM injecté
avec linkedom, `vi.fn`). Règles : aucun attribut `style`, jetons `--pp-*` uniquement (liste dans
`packages/tokens/generated/tokens.json` : n'en invente aucun), propriétés logiques, aucun texte en
dur (libellés en props), jamais la couleur seule, ni dégradé, ni ombre, ni flou, aucun nombre
magique (constantes nommées), `import type` pour les types. Fichiers ≤ 120 lignes (découpe en
`.css` global ou en modules si besoin). Cibles tactiles ≥ `--pp-size-target-min`.

## Diagram

Schéma SVG accessible : le composant **n'écrit pas le SVG**, il l'enveloppe. API : `id: string` (obligatoire), `title: string`, `description: string` (alternative textuelle complète), `caption?: string`, `viewBox: string`, `scroll?: boolean`, slot par défaut = contenu SVG (`<g>`, `<path>`…). Rendu : `<figure>` ; `<svg role="img" aria-labelledby="{id}-t {id}-d" viewBox focusable="false">` avec `<title id>` et `<desc id>` ; `<figcaption>` si `caption`. Le SVG est fluide (`inline-size: 100%`, `block-size: auto`), les couleurs sont héritées (`currentColor`) ou viennent de jetons dans le CSS global `diagram.css` (classes `pp-diagram__line`, `__box`, `__label`, `__accent` à utiliser dans le slot) : ni dégradé, ni ombre, ni flou. `forced-colors` : tout en `CanvasText` et `Canvas`. Un schéma plus large que l'écran doit être simplifié ou défilable : avec `scroll`, le SVG est dans un conteneur `tabindex="0"` au nom accessible (`role="group"` et `aria-labelledby` vers le titre) et `overflow-inline: auto`. La page de doc contient un exemple réel (3 à 5 blocs reliés par des flèches, par exemple « tokens → css → astro »). Le CSS va dans `diagram.css`, importé par le composant.

Le champ `Props` documente chaque propriété. **Déjà posés par l'orchestrateur** : l'export
`@paulperigault/astro/Diagram.astro`, l'entrée de navigation, un fichier de composant, une page et
un fragment de registre provisoires que tu **remplaces** (mets le schéma shadcn comme
`status.json`, `"tokens": []` : `npm run registry` les recalcule ; liste dans `files` du fragment
tous les fichiers du composant, y compris `.css` et behaviors). Le test couvre : rôles, noms
accessibles, attributs selon les props et défauts, aucun attribut `style`, un cas limite par prop,
et la logique pure des behaviors.

Page de doc `apps/docs/src/pages/components/diagram.astro` sur le gabarit
`../../components/ComponentPage.astro` exactement comme `components/status.astro` (lis-la : `slug`,
`title`, `summary`, `use`, `avoid`, `snippet`, `a11y` avec ses quatre listes, `evidence` avec liens
vers la norme WCAG ou le motif APG qui s'applique) ; les exemples vivants sont dans
`components/examples/diagram.astro`. Français simple, phrases de 25 mots au plus, faits seulement.
Chaque affirmation d'accessibilité cite un critère WCAG numéroté ou un motif APG ; ce que tu n'as
pas pu vérifier est dit comme tel.
